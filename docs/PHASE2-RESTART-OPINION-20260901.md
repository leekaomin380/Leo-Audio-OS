## 2. 音量双入口缺陷

### 2.1 当前事实

当前存在两个相互独立的用户音量入口：

1. HIFI 应用的 DAC 音量滑块通过 `leo_hifi_volume` 写 ES9018 `Volume` kcontrol，用户范围 0–60 映射到控件 213–237。
2. 物理音量键改变 Android MUSIC stream，由 AudioFlinger 在数字域调整音量。

两者控制不同增益层，因此会出现双重衰减、状态不同步、恢复语义不清和真实响度难以判断。这应视为产品缺陷。

### 2.2 第二阶段推荐方案

**唯一用户入口应是物理音量键。HIFI 应用只保留开关、真实状态和故障提示，不再提供独立滑块。**

分两级实施：

- **V2.1 低风险收敛**：删除/禁用应用 DAC 音量入口；将 ES9018 固定在经过重新听音确认的安全值，初始验证从出厂基线 205 开始；物理键继续控制 Android MUSIC stream。
- **V2.2 高保真统一**：若测量证明数字衰减值得优化，再修改 framework/AudioService/AudioFlinger，使物理键对应一个统一的系统音量索引；HIFI 路由下由系统把该索引安全映射到 ES9018，同时避免 AudioFlinger 与 DAC 双重衰减。

不得用普通 APK 监听按键后把 MUSIC stream 强制拉满来模拟 V2.2。这会引入竞态、界面假状态和突然放大风险。

### 2.3 验收门槛

- 系统只呈现一个音量入口和一个当前值。
- 插拔耳机、开关 HIFI、重启服务、重启手机及异常回退后响度连续且可预测。
- 最低档、静音、通知、闹钟和媒体音量语义明确；“DAC 用户值 0”不得再与静音混淆。
- 所有硬件写入必须钳位、双声道读回，失败回到安全基线。
- 在假负载或安全耳机条件下测量后，才允许提高固定 DAC 增益。

## 3. SRC 的可解决边界

### 3.1 当前阻塞点

leo 硬件具备 44.1 kHz 与 48 kHz 时钟家族，内核也存在 `KHZ_44P1` 枚举。当前阻塞主要位于 Android 输出路径：

```text
第三方应用 44.1 kHz
  -> AudioFlinger deep-buffer / MixerThread 48 kHz
  -> HAL 固定 48 kHz
  -> QUAT / ES9018 48 kHz
```

当前 HAL 的 `AUDIO_OUTPUT_FLAG_DIRECT_PCM` 分支没有应用可达入口，fallback 又把输出写回 48 kHz。因此配置文件中声明 44100，或只把 `QUAT_MI2S SampleRate` 改成 `KHZ_44P1`，都不能证明 SRC 已消除。只改后端还可能造成前后端速率错配、变调、断流或爆音。

### 3.2 可行范围

- **自有播放器、单应用、单流、本地/缓存 PCM**：可以把 44.1 kHz DIRECT 作为受控原型目标，技术上有实现机会。
- **Spotify、Apple Music、Apple Music Classical**：若继续走共享 deep-buffer，要消除 44.1→48 SRC，需联合修改 AudioPolicy、AudioFlinger 与 HAL；仅改应用或 XML 不足。
- **多流与系统通知**：当音乐和通知具有不同采样率时，不可能让所有流同时保持各自 native rate。第二阶段必须定义谁跟随主时钟、谁允许 SRC，以及何时重开输出。
- **全局 bit-perfect**：在源文件、应用解码、活动线程、混音/音量、HAL/ALSA、后端时钟和可信数字端点全部闭合前不得宣称。

### 3.3 听感收益判断

消除一次高质量 44.1→48 kHz SRC 的听感收益预计为**小或不稳定**，通常小于正确 HIFI 路由、耳机匹配、无爆音运行和统一增益结构带来的收益。

- Spotify 是有损源，进一步消除 SRC 的收益通常更有限。
- Apple Music/Classical 的无损 44.1 kHz 内容在理论上更值得验证，但差异更可能是细微的高频、瞬态或空间感，未必能在音量匹配盲测中稳定识别。
- 高采样率内容被转换为 48 kHz 时测量差异可能更大，但母带差异仍是主要变量。
- 是否继续投入必须由端到端速率证据、失真/噪声测量和音量匹配 ABX 共同决定，不能只凭主观即时印象。

## 4. 第二阶段建议顺序

1. 冷启动只读核对 Git、候选产物、手机 HAL 哈希、boot ID 与回滚路径。
2. 修复并发 usecase 活动集合/引用计数。
3. 完成 V2.1：撤下独立 DAC 滑块，建立物理键唯一入口和安全固定增益。
4. 测量现有 48 kHz SRC 基线，包括不同应用、不同源采样率和通知并发。
5. 做自有播放器的 44.1 kHz DIRECT 最小原型；必须在 QUAT 关闭时切换速率，并完成前端、ALSA、HAL、后端与时钟读回。
6. 只有原型稳定且测量/盲听显示收益后，才评估第三方应用的 framework 级动态采样率以及 V2.2 DAC 音量映射。
