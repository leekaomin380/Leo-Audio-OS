## 2. 目标与下一步

**当前主目标**：让 MoKee 上的 ES9018K2M 通路在音质与功能上达到 MIUI 参照水平（Phase 5B）。

**本轮已完成部分**

- 纯 XML 改动即可完成 ESS 路由，已在机证明。
- MIUI 的 `hifi_volume` 映射链完整逆向。
- ACDB `-1` 之谜解开，并据此关闭「找出正确 ESS ACDB ID」这一开放项（答案是 10）。
- 「校准 / DSP」类假设全部清空。
- 抓出一个会使既往 THD 观测全部失效的采集时机缺陷。

**关键阻断**

1. 241 处报告的「细节增加」未分离：纯响度效应 vs 内部衰减减少带来的真实量化损失下降。
2. `compress-offload-playback2` 无 hifi 路径 → 该场景静默无声。
3. 开机持久化需要分区写入，**未授权**；当前一切改动重启即失效。
4. `-fno-common` 下 `use_case_table` 重复定义 ×11，M3 baseline 未产出。

**接班后优先做的三件事**

1. **闭合分离实验**（附件 B §4）。这是唯一挡在「是否移植 `hifi_volume` 映射链」决策前面的问题。设计：ESS 置 253，反向降 Android 音量凑 WCD 响度。方法本身不干净（降 Android 音量会在上游引入新的数字衰减），需在报告中注明。
2. **评估 `hifi_volume` 映射链在 MoKee HAL 中的最小移植面**。完整链条见附件 A §3。
3. **不要动 ACDB**。附件 A §4.3 与附件 B §2 双重支持。

## 8. 操作与风险

### 8.1 本轮实际修改了什么

**设备端**，写操作仅三类：

1. `mount --bind` 覆盖 `/vendor/etc/audio_platform_info.xml` 与 `/vendor/etc/mixer_paths.xml` —— **已全部卸载**。
2. `killall audioserver` ×2（进入与回滚各一次）—— init 自动重启，当前 pid 3589。
3. `tinymix Volume` 写入 `229 → 241 → 247` —— **已复位至 205**。

**未做**：写分区、改 property、安装组件、重启手机。

### 8.2 当前有效状态与恢复材料

`/vendor` 分区**全程只读、字节不变**。回滚脚本已逐一核对 sha256：

```
8fa544779068490bcc81bd264380d508fe831b06e2023ad9381be79dedffe523  /vendor/etc/audio_platform_info.xml
13db0e6e5bd04e02c36a6b84e815f492d730e107866b91e605ee653364084bb4  /vendor/etc/mixer_paths.xml
```

`mount --bind` 的性质决定了**重启即自动还原**，无需恢复材料。实验候选文件与脚本留在 `/data/local/tmp/leo-exp/`，可重复使用。

### 8.3 本轮新发现的工具缺陷（已修，但影响后续所有轮次）

`pkill -f "leo-exp-watchdog.sh"` 会匹配到**执行它的那条 adb shell 命令行本身**，导致 shell 自杀（exit 143）而看门狗存活。R6 曾修过 `grep` 的自匹配（改用 `leo-exp-watch[d]og`），但 `pkill` 的模式串未修。

**建议接班者采纳为规范**：所有终止后台进程的路径统一改为「`ps -A -o args | grep "模式[中]插方括号"` 取真实 PID → `kill -9 <pid>` → 复查残留数」，禁用 `pkill -f <自身可见的模式>`。

### 8.4 一条采集规范（建议双方共同采纳）

任何 ES9018 kcontrol 读数，若采集时 `QUAT_MI2S_RX Audio Mixer MultiMediaN` 全为 Off 或 `HPHL DAC Switch=On`，一律视为**无效**。理由见附件 B §1。
