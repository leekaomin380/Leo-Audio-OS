# AGY 用户触发交接协议 v1.0

2026-08-30。依据用户本轮明确指令制定，适用于 Codex 与 Claude 轮流担任当班架构师、协调 agy 的工作方式。

**结论：可行，采用用户触发的显式交接。** 用户判断额度和交接时机；当班架构师负责收口成果、写交接书；接班架构师负责核对并接管。

本协议取代共同能力说明及 Codex 复核意见中关于自动额度触发、自动接棒的规划。当前不建设额度监测器或自动交接系统；未来是否需要，另由用户决定。其他任务隔离、独立验收和授权边界继续适用。

本协议是交接流程，不是本次立即交接、启动 agy 或扩大项目操作权限的指令。旧版文档保留，不覆盖。

## 1. 谁决定何时交接

- 用户观察当班架构师的剩余额度。用户发现其不足 10%，且相关 agy 均已停止时，下达交接指令。
- 收到指令的当班架构师立即进入收口阶段，不再派发新任务、续接 agy 或扩大研究范围。
- 接班对象由用户指令确定；仅有 Codex/Claude 两位时，“交给另一位”已足够明确。
- 架构师不自行假定额度不足，不因达到某个推测阈值自动接棒。

10% 是用户的触发参考，不保证剩余额度足够完成所有验收。日常每批任务交付后就更新简短任务账本，避免把全部整理留到最后。若已知验收积压明显，及时告知用户，不擅自接棒。

## 2. 收到指令后的固定动作

1. **停止派发，核对静止状态。** 对照任务账本核查本批 agy 会话及其已登记子进程、构建任务是否仍在运行。模型已回复不等于后台命令已结束。不为交接擅自杀进程，也不触碰用户的其他 agy 会话。发现仍在运行的任务就登记并说明交接条件尚未满足。
2. **清点所有交回成果。** 每个 job 记录输入身份、输出位置、关键产物哈希、原始日志、退出状态与尚未处理的问题；失败、取消和没有交付的任务也必须登记。
3. **处理交付与验收。** 优先进行低成本且决定性的检查，区分“已交付”和“已验收”。不要为使状态好看而重跑大构建、启动新的 agy、放宽验收条件或修改输入。需要返工的，写清返工项并移交，不在收口阶段重新派发。
4. **额度紧张时先保证完整交接。** 可以移交尚未验收的成果，但必须明确标为 `DELIVERED_PENDING_REVIEW`，写出未做的检查和证据位置；不能默认通过，也不能只留下一个笼统的“待处理”。
5. **写交接书并核对引用。** 保存为新的、带时间与唯一交接编号的文件，不覆盖旧交接书。确认接班者能定位工作区、成果和日志，完成后给用户交接书路径。
6. **进入待接管状态。** 前任停止主动调度及项目变更。接班者核对交接书后，以交接编号明确确认接管，才成为新的调度负责人。

前任收到交接指令后的职责是完成可行的收口，不是保证所有成果都已通过验收。**清点必须完整，验收状态必须真实，未完工作必须可继续。**

## 3. 交接书最低内容

| 项目 | 必须记录 |
|---|---|
| 交接身份 | 交接编号、生成时间、用户指令时间、交出方、接班方、当前交接状态 |
| 目标与下一步 | 当前主目标、已完成部分、关键阻断、接班后优先做的 1–3 件事 |
| 权限边界 | 当前明确授权的范围及依据、禁止事项、哪些动作仍需另行授权；历史授权不自动成为新的写入授权 |
| 工作区状态 | 实际工作目录、相关分支/HEAD、未提交变更和归属、不可触碰的其他工作树；不得把未提交成果遗漏在 HEAD 之外 |
| agy 任务账本 | job ID、明确的 conversation ID、输入身份、输出/日志位置、关键哈希、任务结果、验收状态及返工项 |
| 运行状态 | 核对时间、已登记进程/后台任务是否停止、资源占用是否释放；不能确认的项目标 UNKNOWN |
| 已确认与未确认 | 关键结论及直接证据、被推翻的旧结论、待验收成果、UNKNOWN/MISSING 和所需检查 |
| 操作与风险 | 本轮实际修改了什么；如涉及获授权的系统变更，记录当前有效状态和恢复材料；不把计划写成已部署 |

账本可以直接引用已有清单，交接书只写增量与索引，不复制整段聊天或全部原始日志。不在交接书中复制密钥、令牌和无关个人数据。

建议任务状态：`ACCEPTED`、`DELIVERED_PENDING_REVIEW`、`REWORK_REQUIRED`、`BLOCKED`、`FAILED`、`CANCELED`。运行状态单独记录；`STOPPED` 不是验收通过。

## 4. 接班规则与异常处理

- 用户把交接书交给接班者，或明确要求其读取。当前协议不自动向另一个会话发送消息。
- 接班者先核对交接编号、关键文件身份、相关工作树状态及未结束任务，不重复整轮已完成验收。
- 若没有冲突，明确回复“已接管交接编号 X”，登记负责人。缺少会影响安全或正确性的关键证据时，先补核查；不得把前任的未知项变成已验证。
- 同一时刻只有一个调度负责人。前任可应询解释证据，但不再自行启动 agy 或操作工作区。
- 交接书完成后才到达的旧任务结果，不自动进入新一轮。按旧 job 和交接编号标记为迟到结果，交接班者单独验收；不得覆盖已冻结成果。
- 如果额度突然耗尽而来不及完成交接书，已有任务账本及原始成果作为恢复依据，明确属于“未完成交接”。接班者先重建运行与成果状态，不能假定 agy 全停或成果已验收。
- 交接不自动批准删除、刷机、安装、部署、服务器变更、合并或推送；这类动作仍按当前用户明确授权和对应流程执行。

- 核对时间：

- 任务账本位置：

- 已交付待验收（每项附缺失检查）：

- 证据、日志和关键产物身份：

执行顺序固定为：**用户指令 → 停止派发并核对任务停止 → 清点及如实验收 → 交接书 → 接班确认 → 恢复调度。**
