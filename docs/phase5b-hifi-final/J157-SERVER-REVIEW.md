# 文件服务器电源策略审定

用户明确授权保持服务器在线。旧power-loss-shutdown.service每2秒检测AC，online=0即关机，已备份后停用并取消自启。今天日志中有多次正常关机，但没有每次触发者完整记录，不能声称全部均由此服务引起。

新策略：合盖/idle/suspend/hibernate动作忽略；5个睡眠targets已mask，logind热重载，PID保持。新增低电量守卫只在AC=0、BAT0处于Discharging、capacity<=5连续3次10秒采样时请求正常关机（首次到第三次相隔20秒，阈值跨越到动作约20–30秒）。AC短时断开且电量足够不会触发关机。

本地8项测试通过；服务器unit语法检查、--check只读检查和运行状态回读通过，AC1、电池100。未进行拔电源、合盖或实际关机测试。sysfs读数缺失时守卫不自行关机；这可避免误关机，但不保证电池硬件或状态接口故障下仍能提前安全退出。保留过热/电池耗尽等物理限制和手动管理员关机能力。

原服务、安装前状态、文件hash与可回退脚本保存在 /var/backups/leo-always-online-20260831-1148；rollback.py先要求AC在线、检查所有安装文件hash，再恢复旧策略。回退会恢复“断电立即关机”，不能随意运行。

J157对缺失/usr/bin/systemctl的建议不适用于已核验的这台主机，未部署该泛化修正。其额外回退脚本超出分配文件范围，未采用。实际运行代码与已测试、已备份的版本保持一致。SSH/SMB进程未重启，未改网络、共享或服务器其他配置。
