## 1. 交付目标

这两项属于 M3 的 **48 kHz HiFi 基础版**，不推迟到 M3.5 SRC，也不以突破 SRC 为前置。

1. 用户可直接开启或关闭 HiFi，无需电脑、ADB 或手动 mixer 命令。
2. 下拉快捷设置提供名称为 **HIFI** 的开关；设置页提供同一状态入口及独立 HiFi 音量入口，避免两个不同的状态来源。
3. **顶部状态栏显示可辨认的 HIFI 字样，按类似电池旁系统状态标识的方式实现与验收**；不能仅在下拉通知卡片中显示标题就算完成。下拉面板另提供开关和详细状态入口。
4. 常驻指状态栏可见且 HiFi 实际工作期间稳定显示；不能随“清除全部通知”消失，也不能只在应用前台存在。全屏应用主动隐藏整个系统状态栏时，不要求额外悬浮窗覆盖内容。字形、间距、位置、浅/深色背景及锁屏的可读性均做真机验收。

## 2. 开关意图与实际状态分离

开关表达已接受的启用意图，顶部无修饰的 `HIFI` 标识表达当前已验证的 ESS 工作状态。点击事件、保存偏好、耳机插入或 property 为 true 均不能直接点亮工作标识。

| 场景 | 快捷开关 | 下拉说明 | 顶部 HIFI 工作标识 |
|---|---|---|---|
| 用户关闭，普通路由已确认 | 关闭 | HiFi 已关闭 | 隐藏 |
| 开启意图已接受，但未播放/未插耳机 | 开启 | HiFi 已开启 · 待机/等待耳机 | 隐藏 |
| 开启且 ESS 路由、读回及活动流证据闭合 | 开启 | HIFI · ESS9018 · 实际后端采样率 | 显示 |
| 切换处理中 | 暂不可重复点击，保留最后确认意图 | 正在切换 | 不根据点击乐观新增；原状态证据有效时才保留 |
| 请求失败、旁路、控制器回退或未知 | 按已确认意图显示，附异常；通信失联时不可用 | 未生效/已回退/状态不可用，说明原因 | 隐藏 |
| 服务断开、快照过期或 boot/generation 不匹配 | 不可用 | 状态不可用 | 必须清除，不保留旧成功图标 |

补充规则：

- 关闭请求失败而最后新鲜证据仍证明 ESS 活跃时，不得伪报“已关闭”；显示“关闭失败”并与实际状态保持一致。
- UI 的开关选中状态不宣称音频已进入 ESS；待机、处理中与异常必须可区分。
- 显示 `HIFI` **不代表**无 SRC、bit-perfect 或源音频为 24 位。当前 M3 目标仍为 48 kHz。
- 通知静默：不响铃、不振动、不弹横幅，不因每次状态刷新新增一条通知。拔线/待机/恢复后的更新不得留下旧成功标识。
- 事件驱动更新优先；保留有上限的状态过期机制，不用高频 root shell 或持续网络轮询维持图标。

## 3. 控制权限和现有只读契约

本次用户新需求允许界面发送 **HiFi 启停意图**。这补充旧契约中“UI 仅观察”的产品范围，但不改变“HAL 是 mixer 唯一写入者”的底线。

```text
快捷开关 / 设置页
    → 受权限保护的设备本地控制接口
    → 既有音频参数通道（leo_hifi_mode / leo_hifi_volume）
    → HAL Controller：限幅、路由、写入、读回、回退
    → 本地可信状态快照
    → 快捷开关状态 / HIFI 通知标识 / 详情页
```

- 控制接口必须校验调用方身份与授权，只有固定的类型化操作；不能暴露任意参数、shell、property 或 mixer 写入接口。
- UI 不调用 `su`、`tinymix`，不写 property，不获得通用 root 能力；不把现有 HTTP 状态桥改成写入口。
- 观察接口与控制接口分开。保留现有 `AudioStatusProvider` 只读语义；不向其中塞入硬件控制方法。
- 开关失败、权限拒绝、HAL 不支持、回读不一致都必须反馈；参数调用返回成功不等于路由成功。
- 默认首次启动关闭，不擅自提高 205 安全基线。用户启用偏好、音量保存以及重启恢复需单独设计和验证；不能把当前 `vendor.leo.*` property 写入视作已经具备跨重启保存。
- 锁屏点击策略先采用解锁后控制，防误触；后续如用户另有偏好再调整。

## 4. Android 接入与范围

用户已确认顶部系统状态标识，因此 **SystemUI 集成评估进入本需求范围**。下拉快捷磁贴可评估 Android 10 的 `TileService` 或同版本 SystemUI 原生磁贴；标题为 `HIFI`。用户添加到面板或 ROM 默认预置的方式需在集成时明确，不假设安装后自动出现。

普通通知的标题显示在下拉通知中；顶部显示的是 small icon。因此仅设 `setContentTitle("HIFI")` 不满足要求。普通应用通知字形图标只能作为开发预览，**不能默认替代用户确认的系统状态标识**。

实现前需要锁定实机 MoKee SystemUI 的源码/资源、构建签名与安装身份，明确最小修改与回退材料；不能拿不匹配版本的 SystemUI APK 替换，也不因增加标识就默认重建或替换整个 framework。当前主线 HAL＋镜像准备可继续，但基础产品最终验收增加这一项，工作量与签名/构建条件须实查后估算。
