# Phase 3 Gate 0：ROM 输入与 sparse 容器评审

日期：2026-08-24

## 结论

Gate 0 通过。锁定的 Xiaomi Mi Note Pro `V9.2.3.0.NXHCNEK` Fastboot ROM 身份、tar
结构、system sparse header、物理分区容量和 persist 不写边界一致。现有 `simg2img` 与
`img2simg` 可以在本机完成 sparse → raw → sparse → raw，往返后的 raw system 与原始
raw system 逐字节哈希相同。

本结论仅覆盖 Android sparse 容器层，不覆盖 ext4 文件级解包、元数据保存或重建。

## 输入证据

- ROM：`leo_images_V9.2.3.0.NXHCNEK_20171229.0000.00_7.0_cn_4ca14075f0.tgz`；
- ROM 大小：1525882677 bytes；
- ROM SHA-256：
  `007d3d7d9a7e3e70684498070bab03ec145a73b1de44ed7299698cc4bf5ad94f`；
- `system.img` tar member：1368173500 bytes；
- sparse：v1.0，header 28 bytes，chunk header 12 bytes，block 4096 bytes；
- blocks：425984；chunks：7416；
- 展开容量：1744830464 bytes，等于 rawprogram 中 3407872 × 512 bytes；
- system 物理容量：1703936 KiB；
- persist：32768 KiB，`filename=""`，原厂 rawprogram 默认不写入。

## 安全与清理

- 没有调用 ADB、fastboot 或原厂刷机脚本；
- 没有挂载、修改或写回 system；
- 没有触碰 boot、recovery、persist、modem、Bootloader 或用户数据；
- 四个新生成的临时镜像在哈希确认后按精确路径删除，只保留私有 JSON 报告；
- 清理后数据卷约 28 GiB 可用。

## Gate 1 缺口

当前 macOS 已有 `simg2img`、`img2simg` 和 Android 平台附带的 `mke2fs`，但没有可用于
完整只读审计的 `e2fsck`、`debugfs`、`tune2fs`，也没有能够从文件树恢复 Android
UID/GID、capabilities、xattrs 与 SELinux 标签的完整受控工具链。

下一步应准备受控 Linux ext4 环境。Gate 1 先只读导出 superblock 与完整元数据清单；
在这些清单可验证之前，不开始文件级重建，也不安装或刷入任何 Phase 3 产物。
