# MoKee HIFI 开关与顶部标识：实现与验收报告

状态：**HOST_VALIDATED / NOT_DEPLOYED**。2026-08-31，Codex 轮值架构师。

本批已完成源码实现、独立修正、主机验证和 ARM 诊断候选。**没有完整 SystemUI 安装包，没有刷机、安装、重启 audioserver 或提高手机音量；手机界面尚未改变。**

## 已实现的交互

| 入口或状态 | 当前源码行为 |
|---|---|
| 下拉快捷设置 | 原生 `hifi` 磁贴，标签 HIFI；点击请求开启／关闭，显示待机、播放、等待确认或异常 |
| 默认布局 | 默认及可选磁贴列表追加 hifi；工厂及磁贴均限制设备代号 leo。保留已有用户排序，老用户可从编辑面板添加 |
| 顶部状态栏 | 原生系统图标槽 `leo_hifi`，单色 HIFI 字形；走系统图标及深浅色机制，不创建常驻通知 |
| 何时亮起 | schema2 有效、ESS 驱动绑定、HiFi 路由、MM1 QUAT 前端、WCD 模拟出口关闭、实际 S24_LE/48 kHz 后端、左右音量一致且在 205–237、无错误，并有新鲜 PCM 帧推进证据 |
| 开启但没有播放 | 磁贴显示已开启／待机，顶部不亮 HIFI |
| 退出、失败、过期 | 路由代次作废旧帧证据；超时清除旧状态。失败的关闭请求不得用“无音频流”冒充路由已退出 |
| 长按磁贴 | 解锁后打开 SystemUI 内的独立 DAC 音量面板，0–60，显示左右回读；拖动不写入，点击应用才写入 |
| 音量安全 | 0 不是静音，面板明确提示；user=0 对应控件 213，高于基线 205，必须主动应用；不自动恢复音量、不改变音量默认值或上限 |
| 控制权限 | 同进程调用 AudioSystem，HAL 唯一写 mixer；只允许主用户 SystemUI 进程控制，禁止锁定状态、未解锁用户和次用户发起控制，无新导出服务／socket／root 桥 |
| 超时与重启 | 单一串行工作线程；主线程独立过期定时器；迟到请求不确认、不保存偏好，必须重新读取。音频服务 session 变化清除旧证据 |
| 保存偏好 | 仅保存确认后的开关意图，设备保护存储；首次默认关闭，支持且主用户解锁后恢复；不保存和自动重放音量操作 |

音频流检测本批只覆盖 **MM1／deep-buffer／S16 PCM**。其他前端、压缩 offload、直通高位深没有相应的流证据时不会亮标，不冒充已支持。后端 S24_LE 不代表音源或 Android 输出也是 24 位。

图标槽属于系统状态区域，但与电池的精确排序、窄屏溢出、锁屏、深浅色及字形可读性还须真机截图验收。`preview/glyph-proof.png` 只是源矢量字形在放大、24 px、17 px 下的离线检查，**不是手机截图**。

独立 Android“设置”应用中的 HiFi 设置页入口尚未接入；本批控制入口是快捷磁贴及其长按音量面板。物理音量键仍按系统原有逻辑工作，没有改成直接控制 ESS 寄存器。

## 距离手机可用还差什么

1. 用与目标 ROM 匹配的完整 SystemUI 构建环境生成安装候选，闭合资源／系统签名／权限及回退材料。接口编译不能代替此步骤。设置应用入口也仍需补齐。
2. 完成离线 system 集成及镜像审计；旧 ext4 脚本的几何参数尚不能套用当前 system-b.raw。
3. 在明确设备窗口授权后上机：先确认 HAL 正常加载和 205 基线，再验证开关／插拔／暂停／停止／锁屏／服务重启／错误回退与顶部标识，最后按受控音量步骤试听、回读并截图。
4. 当前构建固定 **48 kHz**。44.1 kHz 时钟族、直通路径和逐级采样率验证属于 M3.5；现有成果**没有突破 SRC，也没有证明 bit-perfect**。

下一轮适合用更高推理档做一次独立跨层审计；重复四路源码生成的收益低于补齐目标构建和真机证据。当前没有修改模型或推理设置。
